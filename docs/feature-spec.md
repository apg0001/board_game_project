# 기능 명세

## 제품 목표

친구들이 같은 Wi-Fi 또는 인터넷 환경에서 모바일/PC 브라우저로 접속해, 설치형 PWA처럼 보드게임을 함께 즐기는 웹앱을 만든다.

초기 목표는 거대한 종합 플랫폼이 아니라 다음 흐름을 안정적으로 완성하는 것이다.

```txt
접속
→ 게스트 닉네임 생성
→ 방 만들기 또는 방 코드 입장
→ 인원에 맞는 게임 추천
→ Ready
→ 게임 시작
→ 실시간 턴 진행
→ 결과 저장
→ 같은 방에서 다시 플레이
```

## 사용자 유형

### 게스트

- 회원가입 없이 즉시 접속한다.
- `Guest_8391` 형태의 닉네임을 자동으로 받는다.
- 같은 브라우저에서는 새로고침 후에도 동일 게스트 세션을 유지한다.
- 방 생성, 방 입장, Ready, 게임 플레이, 채팅을 사용할 수 있다.

### 회원

- ID/Password 기반 회원가입/로그인을 지원한다.
- MVP 이후 전적, 랭킹, 닉네임 변경, 게스트 기록 이관 기능을 확장한다.

현재 완료:

- 회원가입 API
- 로그인 API
- 회원 세션 조회 API
- 프론트 회원가입/로그인 패널
- 인메모리 계정 저장소

### 관전자

- 진행 중인 방에 플레이어 자리를 차지하지 않고 들어간다.
- 비공개 정보는 볼 수 없다.
- 관전 채팅 정책은 방 옵션에 따른다.

## 핵심 도메인

### 게임 카탈로그

- 초기 게임 7종을 등록한다.
- 각 게임은 인원, 예상 시간, 난이도, 카테고리를 가진다.
- 현재 방 인원으로 플레이 가능한 게임만 추천한다.

### 방

- 방 코드는 사람이 읽고 공유하기 쉬운 짧은 문자열이다.
- 방장은 게임 선택, 방 옵션 변경, 강퇴를 할 수 있다.
- 모든 플레이어가 Ready 상태일 때 게임을 시작할 수 있다.
- 방 상태는 `LOBBY`, `PLAYING`, `FINISHED`, `CLOSED`로 나뉜다.

### Quick Match

- 동일 게임 또는 자동 추천 게임 기준으로 대기열에 들어간다.
- 인원 조건이 만족되면 자동으로 방을 만들고 플레이어들을 이동시킨다.
- MVP에서는 다빈치 코드 기준 대기 방 생성/합류를 지원한다.

현재 완료:

- Quick Match API
- 대기 방 생성
- 대기 방 합류
- 방이 가득 차기 전까지 같은 게임 큐 유지
- 프론트 퀵매치 버튼 연결

### 게임 세션

- 세션은 방에서 시작되는 실제 플레이 단위다.
- 서버가 권위 있는 상태를 가진다.
- 클라이언트는 액션만 보내고, 서버는 검증 후 상태와 이벤트를 브로드캐스트한다.
- 게임별 룰은 `gamecore.Module` 인터페이스로 분리한다.

### 게임 종료 후 흐름

- 게임이 끝나면 방은 즉시 사라지지 않고 결과 화면 상태로 전환된다.
- 플레이어는 결과, 순위, 점수, 전적 반영 결과를 확인한다.
- 방장은 같은 방에서 다시 하기를 제안할 수 있다.
- 모든 플레이어 또는 과반 동의가 모이면 같은 방에서 새 게임 세션을 시작한다.
- 플레이어는 로비로 돌아가기, 홈으로 가기, 방 나가기를 선택할 수 있다.
- 방에 남은 플레이어가 없으면 방을 닫는다.
- 방장이 나가면 남은 플레이어 중 가장 먼저 입장한 플레이어에게 방장을 위임한다.

### 재접속

- 네트워크 끊김 후 60초 동안 자리를 유지한다.
- 재접속 시 기존 방/게임 채널에 다시 참가한다.
- 개인화 상태를 다시 내려준다.
- 60초 초과 시 게임별 자동 패스/기권 정책을 적용한다.

### 전적

- 게임별 승/패/무, 플레이 수, 승률, MMR을 저장한다.
- MVP에서는 로컬 DB 모델과 기록 API를 먼저 만든다.
- 리더보드는 MVP 이후 화면화한다.

### F-011 게임 종료 후 액션

상태: 완료

요구사항:

- 결과 화면에서 순위, 점수, 승패를 보여준다.
- `다시 하기` 버튼을 제공한다.
- `로비로 가기`는 같은 방의 LOBBY 상태로 돌아간다.
- `홈으로 가기`는 현재 방 선택을 해제하고 메인 로비로 이동한다.
- `방 나가기`는 참가자 목록에서 사용자를 제거한다.
- 방장이 방을 나가면 방장 권한을 위임한다.
- 방에 아무도 남지 않으면 방 상태를 `CLOSED`로 바꾼다.

API:

```txt
POST /api/rooms/{roomID}/rematch
POST /api/rooms/{roomID}/return-lobby
POST /api/rooms/{roomID}/leave
```

WebSocket:

```txt
game.finished
room.returned_to_lobby
room.rematch_requested
room.player_left
room.host_changed
room.closed
```

완료 기준:

- 게임 종료 후 같은 방에서 다시 시작 가능
- 플레이어가 방을 나가면 다른 클라이언트 참가자 목록이 갱신됨
- 마지막 플레이어가 나가면 방이 닫힘

현재 완료:

- 게임 종료 시 방 상태 `FINISHED` 전환
- 다시 하기
- 로비로 가기
- 홈으로 가기
- 방 나가기
- 방장 위임
- 빈 방 자동 종료

## 비기능 요구사항

### 클린 코드

- 도메인 로직은 HTTP 핸들러에 직접 넣지 않는다.
- 저장소는 인터페이스로 분리한다.
- 게임 룰은 `gamecore.Module` 뒤에 격리한다.
- 함수는 한 가지 책임을 가진다.
- 테스트 가능한 순수 로직을 우선한다.

### SOLID 적용

- SRP: `catalog`, `room`, `guest`, `realtime`, `gamecore` 패키지를 책임별로 분리한다.
- OCP: 신규 게임은 기존 런타임 수정 없이 모듈 등록으로 추가한다.
- LSP: 모든 게임 모듈은 같은 `Module` 계약을 지킨다.
- ISP: 거대한 서비스 인터페이스 대신 작은 저장소/서비스 인터페이스를 둔다.
- DIP: HTTP 계층은 구체 저장소가 아니라 서비스 인터페이스에 의존한다.

### 테스트

- 도메인 로직은 단위 테스트를 먼저 작성한다.
- HTTP API는 `httptest`로 통합 테스트한다.
- WebSocket은 핵심 이벤트부터 통합 테스트한다.
- 프론트는 빌드와 타입 검사를 필수 게이트로 둔다.
